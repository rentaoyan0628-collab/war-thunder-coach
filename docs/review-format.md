# 轻量复盘格式

```json
{"version":"录像版本或unknown","evidence":[{"id":"e1","availableAt":120,"type":"video","statement":"画面事实","path":"截图或来源"}],"claims":[{"id":"c1","text":"最终呈现内容","evidenceIds":["e1"],"use":"decision","decisionAt":120,"optionAvailability":"conditional","verdict":"unrated"}]}
```

use为decision表示评价当时决策，outcome表示解释后续结果。availableAt用录像秒数。无需精确时刻时省略decisionAt，不冒称反应迟缓。referenceVersion可记录参数适用版本；没有版本时说明未知。额外字段可用于动作阶段、地图位置、语音、候选车型及数值来源。

校验只核对证据引用、后见信息、不可用动作和版本提示，不证明模型识别正确。不因未知车型拒绝输出。

## 教练层（coach）

校验检查结构，教练层解释行动与选择；字段齐全不能保证识别或判断正确。正文优先动作、收益及条件分支，不确定依据放结构化字段。

`use: "decision"` 的条目必须带 `coach`，四段缺一不可：

```json
"coach": {
  "options": ["那一刻能做什么（含「不做」）", "另一个可选项"],
  "did": "实际做法",
  "cost": "这个选择付出了什么",
  "nextTime": "下次可执行、可验证的一句话"
}
```

- **options**：只写在当时信息下真实可执行的选项；事后才知道的解法不算。
- **cost**：有实际代价就写实际代价；未见代价放证据备注，条件风险可写为条件分支。
- **nextTime**：必须能被下一份录像验证——写清楚要拍什么、看哪个 HUD 元素、什么算做到。

### 硬规则

1. 可根据证据给出判断；全为 `unrated` 也允许，不为凑评级强判。感知或操作可用时间未知时用条件分支，不声称反应迟缓。
2. `coach.nextTime` 不允许为空。
3. `verdict` 含义：`good`/`bad`/`questionable` 是有判断，`unrated` 是明确放弃判断并说明原因。

`use: "outcome"` 的条目建议带 `takeaway`（一句可迁移的经验）；没有可迁移内容时省略，不要凑字数。

### 教练层不做什么

不评价录不到的东西。没有空战画面就不评换机时机，没有受击过程就不评停车位置，没有开火后画面就不评是否被反打——缺失画面记录在证据或备注；对用户有用时给出符合当时信息的条件分支。

## 用户表达偏好
# 复盘表达修订：条件分支与证据字段

用户2026-11-24明确：不确定信息下沉到结构化证据、availability、confidence或备注字段；教学正文以观察、动作、结果与条件分支为主。感知时间或操作可用时间未知时，写“如果当时能确认X且动作可用，就可以Y”，不要断言“应该更快”或假装已经看见X。条件不是已发生事实，也不能通过条件句把不可行操作包装成建议。影响关键结论的未知、素材缺失或用户需知的限制仍简洁说明。

不要为满足评级要求强行打分；无法评判时可unrated并继续提供有用条件分支。缺少某个画面只放证据/备注，不要求每条教学建议都写补录指令。复盘要讲清楚可见走线与战术意图，不以一连串“无法确认”代替教学。此修订不改变用户提供经验、独立视觉与推断的来源记录。
